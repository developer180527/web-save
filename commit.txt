Wire up the edit actions

The first writes across the bridge: star, read, check-now, delete and
open, reachable from the detail pane, the row's hover actions and the
long-press sheet.

Every mutation returns the save as core now holds it, and that value
replaces the row. Nothing is guessed locally, so the UI cannot drift from
the vault, and a 500-row list never refetches because one star changed.

That needed somewhere for the list, the selection and the pending checks
to live, so SavesController (a plain ChangeNotifier -- the whole mutable
state is a list, a selection and two flags) replaces the FutureBuilder.
It is what keeps the list, the detail pane and the stats strip showing
the same save: one write moves all three.

Check-now tracks a per-row pending state rather than a global loading
flag, so re-checking one link does not grey out the list, and the button
disables rather than hides so it does not move under the cursor. Failed
writes surface as a SnackBar -- a silent failure would look like a missed
click. Delete confirms; a dead link goes to Trash with a grace period,
but an explicit delete is immediate.

Open launches the system browser rather than an in-app view: the user's
session, extensions and blockers live there.
