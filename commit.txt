Let the Flutter build compile Rust

Adopts cargokit, the documented integration backend, so the crate is
built as part of flutter run/build on every platform. Previously each of
the three Rust binaries was built by a hand-run script and the bindings
carry a content hash both sides check at startup, so editing the bridge
and rebuilding only the host failed on device with a mismatch that named
neither the file nor the missing target.

macOS was the real breakage. It never linked the library at all: the
loader searched the source tree for a dylib, looked only in target/debug
regardless of build mode, and walked eight parent directories up from the
executable. That worked when launched from inside the repo and failed, or
silently found a stale build, anywhere else — so release builds did not
run. The library now ships inside the bundle and the search is deleted.

Renames the crate to websave_bridge. Cargo tolerates a hyphen but emits
underscores in artifact filenames, so cargokit looked for a static lib
that never existed and fell through to a dylib path that threw; dart pub
add rejected the same name outright.

iOS keeps -force_load, now declared by the pod rather than by us against
a hand-built archive. Rust.xcconfig keeps only the system libraries
cargokit cannot know about, which a Rust staticlib records as link
directives cargo has no way to pass to Xcode.

Verified: macOS release runs from outside the repo, and the app builds
and runs on a physical iPhone with no duplicate symbols.
