Bring the card view, sidebar filters and editing across

Closes most of the UI gap with the React app.

The sidebar gains its sections, the link-health filters and the tag list,
each with counts read from the vault rather than from the loaded page --
so a count stays true while the list is showing something else. Filtering
happens in SQL via ListQuery rather than by filtering a fetched list in
Dart, which is the difference between an index scan and shipping every
row across the bridge.

Card view is a lazily built grid with a max-extent delegate, and three
things make it affordable on a real vault: cacheWidth so covers decode at
display size rather than full resolution, a RepaintBoundary per card so
hover does not repaint the grid, and a fixed tile extent so tiles are
placed without measuring. Cover height is constant -- letting it flex made
each card's image a different height and the grid read as ragged.

Editing covers title, notes and tags in one dialog, sending only the
fields that changed: core treats null as "leave alone", so an untouched
field cannot overwrite what the extension wrote meanwhile.

Adds the ios, android, windows and linux platform folders. The bridge
crate is confirmed to cross-compile for aarch64-apple-ios; linking it
into the Xcode target is still to do.
