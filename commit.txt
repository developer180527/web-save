Add the detail pane, a custom title bar, and a platform floor for shells

Three things, all about the desktop feeling like a desktop.

The shell rule was too absolute. "Layout follows width, never platform"
conflated how much room there is with which idioms are available: a
bottom tab bar is a thumb idiom, so a narrowed desktop window was getting
a phone's navigation. Shell selection is now min(what the width affords,
what the platform offers) -- desktop floors at the icon rail, touch
platforms keep all three. That is what keeps the iPad right, where one
device legitimately produces all three answers depending on its window.

The title bar is drawn by the app on desktop and absent everywhere else,
keyed off platform rather than width so an iPad at desktop width still
gets none. It mirrors the Tauri chrome: macOS keeps its native traffic
lights and reserves their footprint, Windows and Linux go frameless and
draw their own controls, and close hides rather than quits so capture and
monitoring keep running.

SaveDetail serves both the desktop pane and the pushed route, with the
pane/route decision made in one place in the list. The status badge tints
the health colour rather than using it flat, so a dead link reads as
information rather than an alarm.

flutter_theme_engine moves from a path dependency to git, pinned -- this
app is the package's integration test, so it should consume it the way
any other app would.
